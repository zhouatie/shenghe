# 价值突变雷达

Next.js 本地实战投研工作台：观察池、60/40 评分、板块轮动数据、主线雷达、持仓体检、复盘日记和本地 JSON 导出。

本工具只用于个人研究流程管理，不提供收益承诺、价格预测、买卖时机或具体投资建议。

## 环境要求

- Node.js 22 或更高版本，项目使用 `node:sqlite`
- pnpm

如果本机默认 Node 低于 22，可以临时把高版本 Node 放到 PATH 前面：

```bash
PATH=/opt/homebrew/bin:$PATH pnpm dev
```

## 启动

```bash
pnpm install
pnpm dev
```

打开 `http://127.0.0.1:4173`。如果端口被占用，可以用 Next.js 指定其他端口启动：

```bash
PATH=/opt/homebrew/bin:$PATH ./node_modules/.bin/next dev -H 127.0.0.1 -p 4174
```

## 数据与 mock 说明

项目不再内置观察标的 mock 数据。

- 主数据库：`data/radar.sqlite`
- 初始 JSON：`data/radar-db.json`
- 空库启动时只创建表和默认设置，不会自动生成 `DEMO-*` 标的
- 启动时会清理旧版本残留的模板标的：`sample=1` 或代码以 `DEMO-` 开头的数据
- 不会清理你手动录入、CSV 导入或确认入池的真实标的

## 推荐使用流程

### 1. 刷新板块数据

在“数据台”点击“刷新板块”。

系统会读取两类板块数据：

- 开盘啦：板块强度分，偏持续性和主线强弱
- 同花顺：板块涨幅百分比，偏当日爆发

两类数据量纲不同，系统只并列展示，不做直接相加或平均。

### 2. 查看板块数据

进入“板块数据”区域：

- 看“开盘啦强度榜”判断哪些板块持续性更强
- 看“同花顺涨幅榜”判断当天资金集中爆发方向
- 看“排名曲线”判断上榜、掉榜、抬升、回落
- 点击榜单里的“详情”刷新单板块龙头和强度数据

### 3. 从龙头草稿入池

刷新板块详情后，“龙头草稿”会列出近阶段板块龙头。

点击“入池”才会写入候选池；不点击就不会改变观察池。草稿入池只会生成市场侧字段和证据，不会自动填基本面 40 分。

### 4. 手动维护候选池

也可以在“数据台”手动录入，或用 CSV 批量导入。

CSV 表头：

```csv
code,name,symbol,theme,rs,themeScore,flow,structure,catalyst,growth,position,valuation,cashflow,governance,riskPenalty,price,changePct,volume,tags,thesis,riskNotes
```

系统用 `code` 去重，同一个代码再次录入会更新原标的。

### 5. 使用市场评分建议

当候选标的能匹配到板块数据时，右侧“逻辑卡”会显示“市场评分建议”。

点击“采纳市场分”只会更新：

- 相对强度 `rs`
- 主线强度 `themeScore`
- 资金流 `flow`
- 趋势结构 `structure`
- 催化密度 `catalyst`

不会更新：

- 增长加速 `growth`
- 产业位置 `position`
- 估值匹配 `valuation`
- 现金流 `cashflow`
- 治理透明 `governance`

基本面 40 分必须由你根据财报、公告、估值、产业链位置和治理质量人工维护，或以后接入独立基本面数据源。

### 6. 刷新个股行情

“刷新行情”使用 Yahoo Finance 刷新观察池内标的的价格、涨跌幅和成交量。

系统会按代码推导常见 A 股和港股符号：

- `6xxxxx` -> `.SS`
- `0xxxxx` / `3xxxxx` -> `.SZ`
- `HKxxxx` 或 5 位数字 -> `.HK`

行情刷新只补价格相关字段，不会替你判断买卖。

### 7. 复盘和持仓观察

- “持仓体检”用于记录观察仓、目标仓位和阶段
- “复盘日记”用于记录时代逻辑、价值突变点、市场验证和证伪信号
- “写入复盘”会根据当前逻辑卡预填草稿，仍需要你人工确认内容

## 数据导出

点击页面右上角或复盘区域的导出按钮，访问 `/api/export` 导出当前聚合状态 JSON。

导出内容包括观察池、板块数据摘要、持仓、复盘和核心指标。

## 风险边界

板块轮动数据来自第三方公开市场行情接口，接口稳定性由上游决定。市场评分建议只用于复盘和研究，不等同于买入、卖出、仓位或收益建议。所有交易决策由使用者自行负责。
